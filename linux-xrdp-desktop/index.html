Linux XRDP Desktop

A full Ubuntu desktop in a container, over RDP.

A full Ubuntu 24.04 KDE Plasma desktop in a Docker container, styled to look and feel like macOS, accessible over RDP — built for a fast, responsive remote Linux desktop that actually plays video smoothly.

Open source · MIT

GitHub

What you get

  • Ubuntu 24.04 + KDE Plasma, macOS layout & styling — translucent top menu bar (window title, global application menu, tray, Control Centre, clock), top-left Calendar/Clock/Weather widgets, a centered floating bottom dock with hover-zoom, Mkos-Big-Sur icons, Summaculate traffic-light window controls on the top-left, Breeze Dark theme, and Inter + Fira Code fonts with smooth subpixel rendering.
  • One-click .deb installation — double-clicking a downloaded .deb refreshes APT, resolves dependencies, installs it, and notifies you on completion.
  • H.264 RDP encoding — xrdp 0.10.3 + xorgxrdp 0.10.3 built from source with x264 (Ubuntu's xrdp 0.9.x has no H.264 support). Smooth video playback and snappy window dragging at 1080p.
  • TLS-encrypted RDP on port 3389, with multi-monitor support.
  • Audio both ways — PulseAudio playback and microphone redirection over RDP.
  • Webcam redirection ([MS-RDPECAM]) — client cameras redirected over RDP video-capture channels, decoded (H.264 via OpenH264, plus raw YUY2/NV12/I420) and published as native PipeWire Video/Source camera nodes inside the container. Best efforts are made to keep them working in session: cameras enumerate on demand, pipelines are kept ready and restarted on device switch, and inactive pipelines are stopped cleanly so switching doesn't evict the client.
  • Drive redirection — share client drives; they appear at ~/thinclient_drives/ via FUSE and populate Dolphin's Places sidebar as <Drive> on <ClientName>.
  • Clipboard redirection.
  • VirtualGL — GPU-accelerated OpenGL for headless servers (vglrun glmark2 to test).
  • Preinstalled apps — Dolphin, Konsole, Kate, Gwenview, Okular, Spectacle, KRunner (Alt+Space), Firefox, VS Code, GIMP, Inkscape, Blender, OBS Studio, VLC, LibreOffice, htop, neofetch, git.

Quick start

Deploy with Portainer: create a new stack, paste in the repo's docker-compose.portainer.yml, change RDP_PASS, and deploy. Or with Docker Compose:

  1. Clone the repo and edit docker-compose.portainer.yml to set RDP_PASS.
  2. Run docker compose -f docker-compose.portainer.yml up -d.
  3. Connect with any RDP client to <host>:3389 and log in.

The image is also published to ghcr.io/jmez11/linux-xrdp-desktop. Home directory persists in the rdp_home Docker volume. Pass /dev/dri through for GPU access.

Configuration

  • RDP_USER (default engineer) — desktop username, created on first start, has sudo.
  • RDP_PASS (default ChangeMe123!) — change this. Login password.
  • PUID / PGID (default auto) — host user/group IDs, so the container user matches your host permissions on mounted volumes.
  • TZ (default UTC) — timezone.
  • LIBVA_DRIVER_NAME (default iHD) — VAAPI driver: iHD (Intel), radeonsi (AMD), omit for NVIDIA.

Client setup (mstsc)

Set these before connecting (Show Options):

  • Drives — Local Resources → More → Drives → tick your drives (appear at ~/thinclient_drives/).
  • Audio playback — Local Resources → Remote audio → Settings → Play on this computer.
  • Microphone — same dialog → Record from this computer.
  • Video capture devices — Local Resources → More → Video capture devices → tick your camera(s) (FreeRDP: /camera:device,format:h264). Redirected cameras appear as PipeWire Video/Source nodes and work in major browsers.

Drive shares only take effect on a fresh login — if you tick them mid-session, log out of KDE Plasma completely and reconnect.

Zoom

Zoom works in the desktop — two routes, from the repo's Zoom & Standalone V4L2 Webcam Guide:

  • Zoom Web Client (recommended, zero setup): open Firefox or Edge in the session, go to app.zoom.us/wc (or join from your browser), allow camera and microphone. The redirected camera works directly through PipeWire — no host setup.
  • Native Zoom desktop: extra steps, also in the guide — load v4l2loopback on the Docker host (exclusive_caps=1, card label "XRDP Camera"), pass /dev/video0 into the container, then launch Zoom and select "XRDP Camera 1". The container's on-demand bridge only streams while an app is using the camera, so the physical webcam stays off otherwise. Up to 8 cameras can be redirected at once.

Limitations

  • Webcams (best effort): video-capture channels are built in, but redirection is best effort, not guaranteed for every app. Browsers use the PipeWire camera nodes directly. Zoom is working in the desktop (web client with zero setup; native client via the guide's loopback steps) — other native V4L2-only apps need the same kind of optional /dev/video0 passthrough, described in the repo's Zoom & Standalone V4L2 Webcam Guide.
  • RDP only: no VNC/SSH in this image by design; it's a single-purpose desktop container.

Full details, the Dockerfile, and the compose file are in the repo.
